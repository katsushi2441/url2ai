なぜ作ったか

ホスト型のLLM APIは、どれも「まず人間が登録すること」を前提にしています。

1回だけ推論を必要とする自律エージェントは、アカウントを作り、メールを確認し、 カードを登録してキーを発行する、という手順を踏めません。これは技術的な制約ではなく 手続き上の構造的な障壁です。LLM2APIはそこを外しました。 x402の支払いヘッダを付けてリクエストすれば、そのまま推論結果が返ります。登録するものはありません。

クイックスタート

既存のOpenAI呼び出しがあるなら、ベースURLを差し替えるだけです。

curl -X POST https://x402.bankr.bot/0x444fadbd6e1fed0cfbf7613b6c9f91b9021eecbd/llm2api/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "messages": [
      { "role": "system", "content": "あなたは有能なアシスタントです。" },
      { "role": "user", "content": "この内容を一文で要約して" }
    ]
  }'

Bankr CLI から

bankr x402 call \
  https://x402.bankr.bot/0x444fadbd6e1fed0cfbf7613b6c9f91b9021eecbd/llm2api \
  -X POST -H 'content-type: application/json' \
  -d '{"messages":[{"role":"user","content":"こんにちは"}]}'

応答はOpenAI標準のchat completionオブジェクトで、トークン数を含む usage がそのまま入っています。

API仕様

POST {base}/v1/chat/completions

項目型必須説明
messages配列必須{role, content} の配列。roleは system / user / assistant。
stream真偽値任意SSEストリーミング。既定は false。
temperature数値任意0.0〜2.0。既定は 0.7。
max_tokens整数任意指定値によらず2,048の上限が適用されます。

制限

  • 入力 — 全メッセージ合計で4,000文字まで、メッセージ数は20件まで
  • 出力 — 1リクエストあたり2,048トークンの固定上限

この上限は意図的なものです。1件のリクエストがバックエンドを占有するのを防ぎ、 1コール定額という価格を成立させるために置いています。

その他のエンドポイント

エンドポイント内容
GET /health稼働確認。現在のプロバイダとモデルを返します。
GET /v1/models稼働中のモデル、その枠(ホスト型/セルフホスト)、各種上限。
POST /trade/risk-check暗号資産銘柄のハッキング・上場廃止・訴訟などの直近ネガティブイベント検査。
POST /trade/size-check流動性と注文サイズの診断。

裏側の構成

DeepSeek v4 Flash

x402の有償トラフィックは、レイテンシを安定させるためホスト型の deepseek-v4-flash が処理します。

セルフホストGemma

自社GPU上のGemma 4枠も用意しています。どちらが稼働中かは /v1/models が返します。

コール単位の計測

トークン使用量を呼び出し元ごとに記録しています。価格は推測ではなく実測に基づいて調整します。

正直な制約

  • 個人が運用する小規模サービスです。大手クラウドのような稼働率保証はありません。
  • 上記の入出力上限は固定です。長文ドキュメントを扱う用途には向きません。
  • リクエストは上流プロバイダへ中継されます。第三者のLLM APIに送れないデータは送らないでください。

LLM2API は EXBRIDGE の URL2AI プロジェクトの一部です。 同名の第三者製品とは無関係です。
