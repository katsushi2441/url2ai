Why this exists

Every hosted LLM API assumes a human signs up first.

An autonomous agent that needs one completion cannot create an account, confirm an email, enter a card and provision a key. That signup flow is a structural barrier, not a technical one. LLM2API removes it: send the request with an x402 payment header and you get the completion back. There is nothing to register.

Quickstart

If your code already calls OpenAI, change the base URL.

curl -X POST https://x402.bankr.bot/0x444fadbd6e1fed0cfbf7613b6c9f91b9021eecbd/llm2api/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "messages": [
      { "role": "system", "content": "You are a helpful assistant." },
      { "role": "user", "content": "Summarise this in one sentence." }
    ]
  }'

Using the Bankr CLI

bankr x402 call \
  https://x402.bankr.bot/0x444fadbd6e1fed0cfbf7613b6c9f91b9021eecbd/llm2api \
  -X POST -H 'content-type: application/json' \
  -d '{"messages":[{"role":"user","content":"Hello"}]}'

The response is the standard OpenAI chat completion object, including a usage block with token counts.

API

POST {base}/v1/chat/completions

FieldTypeRequiredNotes
messagesarrayYes{role, content} objects. Roles: system, user, assistant.
streambooleanNoSSE streaming. Default false.
temperaturenumberNo0.0–2.0. Default 0.7.
max_tokensintegerNoHard cap of 2,048 applies regardless of this value.

Limits

  • Input — 4,000 characters total across all messages, 20 messages maximum
  • Output — hard cap of 2,048 tokens per request

These caps are deliberate. They keep a single request from monopolising the backend and keep the flat per-call price honest.

What backs it

DeepSeek v4 Flash

Paid x402 traffic is served by hosted deepseek-v4-flash for predictable latency.

Self-hosted Gemma

A self-hosted Gemma 4 tier runs on our own GPUs. /v1/models reports which tier is active.

Per-call metering

Token usage is recorded per caller, so pricing is grounded in measured consumption rather than guesswork.

Honest limitations

  • This is a small, self-operated service. It is not a hyperscaler and makes no uptime guarantee.
  • The input and output caps above are hard limits. Long-document workloads are not a fit.
  • Requests are proxied to an upstream provider. Do not send data you would not send to a third-party LLM API.
